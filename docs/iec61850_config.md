# IEC 61850 配置文件字段说明

解析代码：`collector-core/src/config/iec61850_conf.rs`
设备实现：`collector-core/src/dev/iec61850_dev/`
协议栈封装：`collector-iec61850/`（基于 libiec61850 的 FFI 封装）
点表生成工具：`scripts/icd_to_iec61850_points.py`
示例文件：`config/iec61850/iec61850_示例点表.xlsx`、`config/iec61850/config_示例.json`

采集器在这里是 IEC 61850 **MMS 客户端（主站）**：主动连接 IED，订阅报告接收遥信遥测，并下发遥控遥调。
目前只做 MMS（客户端），不支持 GOOSE / SV / TLS。

## 配置分两部分

1. **设备参数**：写在项目配置 `config.json` 的 `devices` 里，决定连哪台 IED。
2. **点表**：一份 `.xlsx` 文件，由设备参数里的 `register_file` 指向，决定有哪些点、数据从哪来。

点表**不用手填**：设备厂家给的 `.icd` / `.cid` / `.scd` 文件里有完整的数据模型，用
`scripts/icd_to_iec61850_points.py` 生成初稿，再人工审核补全（见下文"从 ICD 生成点表"）。

### 设备参数（config.json）

```json
"pcs_dev": {
  "id": "pcs_dev",
  "type": "IEC61850",
  "config": {
    "com_type": "IEC61850",
    "register_file": "./config/iec61850/iec61850_示例点表.xlsx",
    "ip": "192.168.1.136",
    "port": 102,
    "interval": 60000,
    "timeout": 5000,
    "iso": {
      "remote_ap_title": "1 3 9999 106",
      "remote_ae_qualifier": 33,
      "remote_psel": "00 00 00 01",
      "remote_ssel": "00 01",
      "remote_tsel": "00 01"
    }
  }
}
```

| 字段 | 必填 | 说明 |
|---|---|---|
| `com_type` | 必填 | 固定为 `IEC61850`。 |
| `register_file` | 必填 | 点表路径，相对路径以采集器的启动目录为基准。未配置或文件打不开时设备无法创建。 |
| `ip` | 必填 | IED 的 IP，必须是合法的 IP 地址（不支持域名）。 |
| `port` | 必填 | MMS 端口，默认 `102`。 |
| `interval` | 必填 | **周期任务间隔**，单位毫秒：定期对每个报告控制块重新触发总召、轮询没有被报告覆盖的点。`0` 表示只在每次连接建立后做一次。 |
| `timeout` | 必填 | 单位毫秒，同时作为连接超时和单次 MMS 请求超时，最小 1000。 |
| `iso` | 选填 | ISO 层地址参数，见下。不填则用库默认值。 |

`slave`、`serial_tty`、`baud_rate` 等其他字段对 IEC 61850 无意义，填 `null` 即可。

#### `iso`：ISO 层地址参数

61850 的 MMS 跑在 OSI 协议栈上，除了 IP 和端口，还有 AP-Title、AE 限定符和三个选择器。**多数设备用默认值就能连上**，
个别设备会校验这些值，不对就拒绝连接。这些值都写在 ICD 的 `<Address>` 段里（`icd_info` sheet 里也有一份）：

| 字段 | 示例 | ICD 里的来源 |
|---|---|---|
| `remote_ap_title` | `"1 3 9999 106"` | `OSI-AP-Title`，空格或点分隔的 OID |
| `remote_ae_qualifier` | `33` | `OSI-AE-Qualifier` |
| `remote_psel` | `"00 00 00 01"` | `OSI-PSEL`，十六进制字节串，最长 16 字节 |
| `remote_ssel` | `"00 01"` | `OSI-SSEL`，最长 16 字节 |
| `remote_tsel` | `"00 01"` | `OSI-TSEL`，最长 4 字节 |
| `local_*` | | 采集器自己的地址，同样的字段，一般不用配 |

没填的项保持库的默认值：TSEL `00 01`、SSEL `00 01`、PSEL `00 00 00 01`，对端 AP-Title `1.1.1.999.1`、AE 限定符 `12`，
本机 AP-Title `1.1.1.999`、AE 限定符 `12`。参数格式不合法时，创建设备就会报错，不用等到连接。

## 点表 Sheet 结构

一个 `.xlsx` 文件，读取两个 sheet：

- `iec61850`：点表。第 1 行是表头，从第 2 行开始是数据行。遥信、遥测、遥控、遥调都放在这里，靠 `type` 列区分。
- `source`：取数来源。每行一个报告控制块（RCB）或一个周期轮询的数据集。

另有一个 `icd_info` sheet（由生成工具写入，记录 ICD 的来源和通讯参数），**采集器读取点表时会忽略它**。

没有 `iec61850` sheet 时点表为空；没有 `source` sheet 时所有点都靠逐点轮询。

## `iec61850` sheet 的列

| 列号(0-based) | 表头 | 必填 | 说明 |
|---|---|---|---|
| 0 | id | 必填 | 点位 `id`，同一份点表内唯一，且不能是 `65535`（保留给通讯状态点）。 |
| 1 | key | 必填 | 业务标识（`DataPoint.key`），点表内唯一，供 `PointRef::Key` 查找、Lua 脚本、下行控制使用。 |
| 2 | name | 选填 | 点位中文名，也可用于 `PointRef::Name` 下发（仅控制点；空名称不参与索引）。 |
| 3 | ref | 必填 | 对象引用，见下。 |
| 4 | fc | 监视点必填 | 功能约束：`ST` `MX` `SP` `SV` `CF` `DC` `SG` `SE` `EX`。也可以直接写在 `ref` 里；两处都写了必须一致。控制点留空。 |
| 5 | type | 必填 | 见下表，不区分大小写。 |
| 6 | scale | 选填 | 浮点数，不能为 `0`，缺省 `1`。仅遥测与遥调生效。 |
| 7 | offset | 选填 | 浮点数，缺省 `0`。仅遥测与遥调生效。 |
| 8 | unit | 选填 | 如 `V`、`A`、`℃`，仅用于展示。 |
| 9 | enable | 选填 | 缺省启用。填 `0` 表示禁用：不参与数据匹配、不被订阅轮询、不可下发。 |
| 10 | trans | 选填 | JSON，如 `{"en": "Voltage"}`，名称翻译。解析失败时静默忽略。 |
| 11 | status_words | 选填 | 状态字：把整数值映射为状态描述，如 `0 分闸\|Open`。格式同 Modbus 点表。 |
| 12 | warn_bits | 选填 | 告警位：**恰好 16 行**，每行 `中文\|英文\|等级`。格式同 Modbus 点表。 |
| 13 | level | 选填 | 单点告警等级：`0`/空/`1`/`2`/`3` 对应 无/`Normal`/`High`/`Critical`，值非 0 即命中该等级。 |
| 14 | ctl_opts | 选填 | 仅控制点，逗号分隔：`interlock`（联锁检查）、`synchro`（同期检查）、`test`（测试位，IED 只校验不真正动作）。 |
| 15 | feedback | 控制点建议填 | 控制点的**回读点 key**，必须是点表里启用的监视点，见"下行"。 |

第 11、12 列有内容但格式不对时，会在日志里记一条 `IEC61850点表 ... 解析失败, 已忽略` 的警告，该列按未配置处理，不影响整行。

### `ref`：对象引用

61850 的数据按层次组织：`逻辑设备(LD) / 逻辑节点(LN) . 数据对象(DO) . 数据属性(DA)`。

| 点类型 | `ref` 指向 | 示例 |
|---|---|---|
| 监视点 | **叶子数据属性**（至少到 `DO.DA`） | `MONT/MMXU1.TotW.mag.f`、`MONT/staGGIO1.Ind1.stVal` |
| 控制点 | **控制对象**（DO） | `MONT/ctlGAPC1.SPCSO1`、`MONT/setGAPC1.StrVal6` |

- 两种写法都接受：点分式 `LD/LN.DO.DA`（FC 写在 `fc` 列，或写成末尾的 `[MX]`），以及 MMS 式 `LD/LN$FC$DO$DA`
  （报告里的数据引用就是这种）。
- LN 名带前缀和实例号，如 `staGGIO1`、`ctlGAPC1`、`setGAPC1`、`dcMMXN1`，照 ICD 里的实际名字写。
- **LD 部分可以只写后缀**：设备上真实的 LD 名是 `IED名 + ldInst`（如 `PCS0001MONT`），点表里写 `MONT` 即可，
  连接后按后缀匹配。后缀匹配到多个 LD 时该点会被忽略并记录告警。这样同型号的多台设备可以共用一份点表。
- 监视点只指到 DO（没有 DA）会被拒绝：结构体没法转成一个数。

### type 取值

| type | 含义 | 方向 | 对应的数据 |
|---|---|---|---|
| `yx` | 遥信 | 上行 | `stVal`（SPS、DPS、INS、ENS、SPC、DPC 等） |
| `yc` | 遥测 | 上行 | `mag.f`（MV）、`cVal.mag.f`（CMV 的各相）、`mxVal.f`（APC 的回读）、`actVal`（BCR）等 |
| `yq` | 品质 | 上行 | 某个数据的品质属性 `q` |
| `ytime` | 时标 | 上行 | 某个数据的时标属性 `t` |
| `yk` | 遥控 | 下行 | `ctlVal` 为布尔的控制对象（SPC、DPC） |
| `yt` | 遥调 | 下行 | `ctlVal` 为数值的控制对象（浮点 APC、INC、ENC 等） |

字符串类的数据（铭牌、版本号）不支持，采集器的数据点只能存数值。

## 上行：值怎么转换

| 点类型 | 收到的值 | 入库的值 |
|---|---|---|
| `yx` | 布尔 | `Val::U8`，`0` 或 `1` |
| `yx` | 双点位置 | `Val::U8`，`0`=中间态，`1`=分，`2`=合，`3`=不确定（与 104 的双点遥信编号一致） |
| `yx` | 枚举 / 整数 | `Val::U8`；超出 `0~255` 的值被丢弃，不会截断成错误的状态 |
| `yc` | 浮点 / 整数 | `Val::F64`，`原始值 × scale + offset` |
| `yq` | 品质 | `Val::U16`，编码见下 |
| `ytime` | 时标 | `Val::F64`，Unix 毫秒时间戳 |

- 类型不匹配（如 `yc` 点收到布尔）、遥测值不是有限数时丢弃；每个点只记录一次告警。
- 32 位浮点按最短十进制表示还原为 `f64`，不会出现 `220.10000610…` 这样的二进制误差。
- **品质和时标是和值同级的兄弟属性**，要采集就单独写一行，`ref` 指向 `.q` / `.t`。协议层不会因为品质异常而丢弃数据，
  是否可信交给下游或脚本判断。

### 品质 `yq` 的编码

按 IEC 61850-7-3 的位定义：

| 位 | 含义 |
|---|---|
| bit0~1 | 有效性：`0` 良好，`1` 无效，`2` 保留，`3` 可疑 |
| bit2 | 溢出 |
| bit3 | 超量程 |
| bit4 | 坏引用 |
| bit5 | 振荡 |
| bit6 | 故障 |
| bit7 | 旧数据 |
| bit8 | 不一致 |
| bit9 | 不精确 |
| bit10 | 被取代（人工置数） |
| bit11 | 测试 |
| bit12 | 操作员闭锁 |

例：`129` = 有效性无效(1) + 旧数据(128)。

## `source` sheet：取数来源

61850 的实时数据来自**报告**：IED 把一个数据集里变化的成员主动推给订阅者。点表里的点不需要写自己属于哪个报告，
采集器按引用自动匹配。`source` sheet 只描述"订阅哪些报告控制块"。

列（0-based）：

| 列号 | 表头 | 说明 |
|---|---|---|
| 0 | kind | `urcb`（非缓冲报告）、`brcb`（缓冲报告）、`dataset`（周期轮询一个数据集） |
| 1 | ref | RCB 引用 `LD/LN.RP.name`（urcb）或 `LD/LN.BR.name`（brcb），也接受 `$` 写法。`name` 末尾的 `*` 通配所有实例。`dataset` 类型则是数据集引用 `LD/LN$name` |
| 2 | dataset | 选填，仅 RCB：改写该 RCB 绑定的数据集；留空沿用 IED 里已配置的（多数 IED 的数据集是固定的，不要填） |
| 3 | trg | 选填，仅 RCB：触发条件，逗号分隔 `dchg`（数据变化）`qchg`（品质变化）`dupd`（数据更新）`period`（周期完整性上送）；留空为 `dchg,qchg` |
| 4 | intg_pd | 选填，仅 RCB：完整性周期（毫秒），`trg` 含 `period` 时生效 |
| 5 | buf_tm | 选填，仅 RCB：缓冲时间（毫秒） |
| 6 | interval | 选填：RCB 定期重新触发总召的周期；`dataset` 的轮询周期。毫秒，留空用设备的 `interval`，`0` 表示不重复 |
| 7 | gi | 选填，仅 RCB：订阅后立即总召，缺省 `1`。设备不支持总召时填 `0` |
| 8 | purge | 选填，仅 BRCB：使能时清空 IED 里的缓冲，缺省 `0`，即**补发断线期间缓存的事件** |
| 9 | enable | 选填，缺省启用 |

### 报告控制块的实例

IED 里可复用的 RCB 通常有多个实例（`urcbAin01` ~ `urcbAin16`），**每个客户端占用一个**，同一个实例同一时刻只能被一个客户端使用。
`ref` 末尾写 `*`（如 `MONT/LLN0.RP.urcbAin*`）时，采集器会列出设备上所有以该前缀开头的实例，依次尝试，
订阅第一个没被占用的。ICD 里 `RptEnabled max` 大于 1 的 RCB 就应该这样写（生成工具会自动加 `*`）。

所有实例都被占用时，该 RCB 覆盖的点会**降级为轮询**，日志里有说明，而不是静默没有值。

## 运行流程

1. 连接 IED（带 `iso` 参数），把点表里的 LD 后缀解析成设备上真实的 LD 名。
2. 对 `source` 里的每个 RCB：展开实例、读取它绑定的数据集的成员和类型、订阅并使能，使能后立即总召一次（`gi=1` 时）。
   报告里的数据集成员往往是整个数据对象（如 `{stVal, q, t}`），采集器按类型展开到叶子属性，再按引用匹配点表。
3. 没有被任何已订阅的 RCB（或轮询数据集）覆盖的监视点，改为**逐点轮询**，日志里会列出这些点。
4. 此后：
   - 数据变化由 IED 主动上送，不依赖轮询；
   - 每隔 `interval`：对每个 RCB 重新触发总召，并轮询上面第 3 步的点，用于校准漏掉的变位；
   - 通讯状态点在订阅完成后置为"通讯正常"。
5. 连接断开：通讯状态置为"无通讯"，退避后重连（500ms 起，翻倍，最长 10 秒），然后整个流程重新来一遍。
   **缓冲报告（BRCB）重连后会补发断线期间的事件**（`purge=0` 时）。

## 下行：遥控与遥调

通过 `DataCenter::dispatch` 下发，下发目标可以按 `id`、`key` 或 `name` 引用。**只有启用的控制点**能被找到。

| 点类型 | 下发值 | 发给 IED 的 `ctlVal` |
|---|---|---|
| `yk` | 任意数值，非 0 为合/true，0 为分/false | 布尔 |
| `yt` | 工程值 `v` | `(v - offset) / scale`，按 `ctlVal` 的类型转成浮点或整数 |

**控制模型自动适配**，点表里不用配：IED 的 `ctlModel` 是直接控制就直接执行；是 SBO（选择后操作）就先选择再执行。
`ctlModel` 为 status-only 的对象不可控，下发会失败。`ctl_opts` 里的联锁、同期、测试位随命令一起发给 IED。

### 命令应答成功不等于设备已执行

很多设备（比如示例里的 PCS，所有控制对象都是 `direct-with-normal-security`）在服务端检查通过后就立刻回成功，
真正执行是异步的，客户端无法从应答得知设备有没有动。所以：

- **每个控制点都应配回读点**（`feedback` 列）：遥控读它的 `stVal`，遥调读 `mxVal.f`。
- 命令应答成功后，采集器每 100ms 读一次回读点，最长等 3 秒：回读值等于目标值，或相对下发前发生了变化，
  就记录"命令已生效"；3 秒内没变化则记录警告"设备可能没有执行"。**只记日志，不影响后续命令。**
- 没有配回读点时只能记录"无法确认设备是否执行"。

命令被 IED 明确拒绝时，日志里会带上 IED 返回的原因（AddCause），如"被联锁闭锁"、"被模式闭锁"、"被其他客户端锁定"。

被拒绝或找不到点的下发，只在日志里记警告，不影响同一批里的其他点。

## 通讯状态点

每个 IEC 61850 设备会自动上报一个通讯状态点，不需要在点表里配置：

| 属性 | 值 |
|---|---|
| id | `65535`（`0xFFFF`） |
| key | `communicationStatus` |
| name | 通讯状态 |
| 值 | `0` = 通讯正常，`1` = 无通讯 |

设备启动后、连接建立前、断线重连期间、停止后均为 `1`；会话建立（订阅完成）后置 `0`。

## 从 ICD 生成点表

```bash
python3 scripts/icd_to_iec61850_points.py 设备.icd -o 点表.xlsx
# 可选: --ied PCS0001   文件里有多个 IED 时指定
#       --ap S1         IED 下有多个接入点时指定
#       --with-quality  同时为每个值点生成品质(q)和时标(t)点, 默认禁用
#       --danger-keyword 词   追加默认禁用控制点的关键字
```

只用 Python 标准库，不需要装任何依赖。运行后会打印摘要：点数、控制模型、默认禁用的控制点、每个 RCB 对应的数据集和点数、警告。

生成的是**初稿**，需要人工审核：

- 点从 ICD 里**数据集**的成员生成，加上所有可控的控制对象；每个控制点自动配好回读点。
- `key` 是机械拼的（`<LN名>_<DO路径>`，控制点加 `_cmd`），`name` 来自 ICD 的 `desc`，重名的会加位置后缀，
  控制点保留干净的名称。`scale`、`offset`、`unit`、状态字、告警位都留空，需要人工补。
  很多"遥测"其实是编码（故障码、站点号等），要补状态字或告警位才有意义。
- **名称含危险关键字的控制点默认禁用**（`enable=0`）：恢复出厂、复位、急停、重启、对时、系统时间。确认后再启用。
- `id` 按数据集顺序分段递增（遥信 1000+、遥测 2000+、遥控 3000+、遥调 4000+、品质 5000+、时标 6000+）。
  **ICD 改版后在中间插入点会让后面的 id 整体移位**，已经按旧 id 做了配置的现场重新生成时要注意。
- `source` sheet 从 ICD 的 `ReportControl` 生成，`RptEnabled max > 1` 的自动加 `*`。
- `icd_info` sheet 记录 ICD 文件名、IED 的 IP 和 ISO 参数，可以直接抄进设备的 `iso` 配置。

## 校验规则

点表解析按行进行，**出错的行会被跳过**并在日志里记 error，不会导致整份点表加载失败。

| 情况 | 结果 |
|---|---|
| 必填列为空、`type` / `fc` / `ctl_opts` 非法 | 该行被跳过，日志说明哪一列 |
| `ref` 格式不对；监视点只写到 DO、没有 DA | 该行被跳过 |
| `ref` 里的 FC 与 `fc` 列不一致；监视点没有 FC | 该行被跳过 |
| `scale` 为 `0` | 该行被跳过 |
| `id` 为 `65535`，或与前面的点重复 | 该行被跳过（先出现的保留） |
| `key` 与前面的点重复 | 该行被跳过 |
| 同一叶子属性（同 FC）有多个监视点；同一控制对象有多个控制点 | 后出现的被跳过 |
| 控制点的 `feedback` 指向不存在（或被禁用）的监视点 | 回读点被忽略，日志警告 |
| `source` 的 `kind` 非法，或 `urcb` / `brcb` 与 `ref` 里的 `RP` / `BR` 不一致 | 该行被跳过 |
| `source` 的 `trg` 含未知的触发条件 | 该行被跳过 |
| `source` 里同一个 `ref` 重复 | 后出现的被跳过 |

`register_file` 未配置、文件打不开时，设备创建失败，日志提示"找不到点位表"。点表能打开但没有点时，设备仍会创建并连接，
只是没有数据，日志会提示"点表中没有启用的监视点"。

运行时的降级（都不会让设备停下）：

| 情况 | 结果 |
|---|---|
| 点的 `ref` 在设备上找不到对应的 LD | 该点被忽略，日志警告 |
| RCB 的所有实例被占用，或 RCB / 数据集不存在 | 它覆盖的点改为轮询 |
| 报告里的值类型与点类型不符 | 丢弃，每个点只告警一次 |

## 示例

`config/iec61850/iec61850_示例点表.xlsx` 由瑞山 RS100 PCS 的 ICD 生成，共 191 个点：

| 类型 | 数量 | 说明 |
|---|---|---|
| `yx` | 28 | 22 路开关量 + 6 个遥控的状态回读 |
| `yc` | 116 | 75 个测量 + 41 个遥调回读 |
| `yk` | 6 | 其中复位、急停、重启默认禁用 |
| `yt` | 41 | 其中系统时间、一键对时、ARM 复位、恢复出厂默认禁用 |

`source` 里有三个 RCB：`brcbDin`（缓冲，13 秒完整性周期）、`urcbAin`（5 秒）、`urcbParameter`（15 秒），触发条件都是 `dchg,period`。

## 联调

没有真实设备时，可以用仓库自带的模拟 PCS：与真实设备同模型（同样的 LD/LN、数据集、报告控制块和控制对象），
构建时由 libiec61850 自带的 `genmodel.jar` 从 `collector-iec61850/tests/data/INPOWER_MMS_1.5.icd` 生成，**构建需要本机有 java**。

```bash
# 终端 1：模拟 PCS，默认端口 9102。每秒有功功率和一路遥信变化一次，遥控 SPCSO6 和遥调 StrVal6 可下发
cargo run -p collector-iec61850 --features server --example pcs_sim

# 终端 2：用示例配置启动采集器
cargo run -p collector-cmd --bin colld -- -c config/iec61850/config_示例.json

# 自动化联调测试（订阅、展开、品质时标、下发读回、断线重连、RCB 被占用降级）
cargo test -p collector-core iec61850_dev
cargo test -p collector-iec61850 --features server
```

连接真机时可以先用探测工具确认通讯参数和模型：

```bash
cargo run -p collector-iec61850 --example probe -- 192.168.1.136 \
    --ap-title "1 3 9999 106" --ae-qualifier 33 --browse \
    --read MONT/MMXU1.TotW.mag.f:MX --rcb "MONT/LLN0.RP.urcbAin*" --secs 20
```

## 常见问题

| 现象 | 排查 |
|---|---|
| 一直"连接中"/"失败" | 核对 `ip`/`port`，确认 IED 允许这个客户端连接；ISO 参数（AP-Title 等）不对时有些设备会拒绝，用 `probe` 对照 ICD 里的 `<Address>` 试。 |
| 已连接，但某个点一直没有值 | 看启动日志：点的 `ref` 是否解析成功；`fc` 对不对；该行有没有被校验规则跳过；它所在的 RCB 是否被占用而降级为轮询。 |
| 日志提示"所有候选 RCB 都被其他客户端占用" | 同一个 RCB 实例同一时刻只能被一个客户端使用。确认 `ref` 末尾有 `*` 以便尝试其他实例；设备上的实例数不够就联系厂家增加 `RptEnabled max`。 |
| 采集器异常退出后立刻重启，RCB 仍显示被占用 | 设备可能还没发现旧连接已断开，使用 `*` 通配会自动换下一个实例；等设备清理旧连接（通常几十秒）后恢复。 |
| 值有但数量级不对 | 检查 `scale`/`offset`。 |
| 下发后日志提示"设备可能没有执行" | 命令应答成功但回读点没变：确认 `feedback` 指向对的回读点；设备可能处于就地模式或被闭锁。 |
| 下发失败，日志有"被联锁闭锁"等原因 | 这是 IED 返回的拒绝原因，按设备的联锁、模式、权限条件处理。 |
| 连接建立要好几秒 | 订阅前要为数据集的每个成员查询一次类型（示例设备共 144 次请求），设备响应慢时连接阶段会比较久，只发生在连接建立时。 |

## 当前限制

- 只做 MMS 客户端。不支持 GOOSE、SV、TLS，一个设备对应一个连接，不支持冗余通道。
- 监视点必须写 `fc`（也可以写在 `ref` 里），不会自动从模型推断。
- 不支持字符串类的数据点。
- 不支持定值组切换（SGCB），不支持整型的 APC 遥调（`ctlVal` 为结构体里的整数）。
- 控制命令只做立即执行，不支持定时控制，不跟踪命令终止（CommandTermination）；是否生效靠回读点判断。
- 不动态创建数据集，依赖 IED 里预配置的数据集。
- 不支持日志服务（LCB/Journal）和文件服务（录波）。
- **以下几点只在模拟器上验证过，需要真机确认**：RCB 实例在真机上的实际命名（是否同样带 `01`~`nn` 序号）、
  设备是否校验 AP-Title 和 AE 限定符、真机上的报告分段与时标内容、BRCB 的断线补发行为。
