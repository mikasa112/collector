# IEC 104 配置文件字段说明

解析代码：`collector-core/src/config/iec104_conf.rs`（`Iec104Config::build`）
设备实现：`collector-core/src/dev/iec60870_dev/`
示例文件：`config/iec104/iec104_示例点表.xlsx`、`config/iec104/config_示例.json`

采集器在这里是 IEC 104 **主站（客户端）**：主动连接对端子站，总召唤、接收遥信遥测，并下发遥控遥调。

## 配置分两部分

1. **设备参数**：写在项目配置 `config.json` 的 `devices` 里，决定连哪台子站。
2. **点表**：一份 `.xlsx` 文件，由设备参数里的 `register_file` 指向，决定有哪些点、怎么转换。

### 设备参数（config.json）

```json
"iec104_dev": {
  "id": "iec104_dev",
  "type": "IEC104",
  "config": {
    "com_type": "IEC104",
    "register_file": "./config/iec104/iec104_示例点表.xlsx",
    "ip": "192.168.1.100",
    "port": 2404,
    "interval": 60000,
    "timeout": 3000
  }
}
```

| 字段 | 必填 | 说明 |
|---|---|---|
| `com_type` | 必填 | 固定为 `IEC104`。 |
| `register_file` | 必填 | 点表路径，相对路径以采集器的启动目录为基准。未配置或文件打不开时设备无法创建。 |
| `ip` | 必填 | 子站 IP，必须是合法的 IP 地址（不支持域名）。 |
| `port` | 必填 | 子站端口，104 默认 `2404`。 |
| `interval` | 必填 | **总召唤周期**，单位毫秒。`0` 表示只在每次连接建立后召唤一次，之后靠子站突发上送。 |
| `timeout` | 必填 | 单位毫秒，用作 TCP 连接超时（t0），换算为整数秒（舍去小数），最小 1 秒。 |

`slave`、`serial_tty`、`baud_rate` 等其他字段对 IEC 104 无意义，填 `null` 即可。

APCI 参数固定为：k=12、w=8、t1=15 秒、t2=10 秒、t3=20 秒。

## 点表 Sheet 结构

一个 `.xlsx` 文件，**只读取名为 `iec104` 的 sheet**，没有这个 sheet 时点表为空。第 1 行是表头，从第 2 行开始是数据行。遥信、遥测、遥控、遥调**都放在同一个 sheet 里**，靠 `type` 列区分。

## 列定义

| 列号(0-based) | 表头 | 必填 | 类型/取值 | 说明 |
|---|---|---|---|---|
| 0 | id | 必填 | 整数 | 点位 `id`，同一份点表内唯一，且不能是 `65535`（保留给通讯状态点）。 |
| 1 | key | 必填 | 字符串 | 业务标识（`DataPoint.key`），供 `PointRef::Key` 查找、Lua 脚本、下行控制使用。 |
| 2 | name | 选填 | 字符串 | 点位中文名（`DataPoint.name`），也可用于 `PointRef::Name` 下发（仅控制点；空名称不参与索引）。 |
| 3 | ca | 必填 | 整数 `1~65534` | 公共地址（Common Address），标识对端的站或逻辑设备。 |
| 4 | ioa | 必填 | 整数 `1~16777215` | 信息对象地址（Information Object Address），填十进制，对端文档写 `0x4001` 要换算成 `16385`。 |
| 5 | type | 必填 | 见下表，不区分大小写 | 点类型，决定是上行监视点还是下行控制点，以及控制命令的编码。 |
| 6 | scale | 选填 | 浮点数，不能为 `0` | 缩放，缺省 `1`。仅遥测与设点生效。 |
| 7 | offset | 选填 | 浮点数 | 偏移，缺省 `0`。仅遥测与设点生效。 |
| 8 | unit | 选填 | 字符串 | 如 `V`、`A`、`℃`，仅用于展示。 |
| 9 | enable | 选填 | `0`/非 0 | 缺省启用。填 `0` 表示禁用：不参与上送匹配、总召 CA 统计和下发。 |
| 10 | trans | 选填 | JSON，如 `{"en": "Voltage"}` | 名称翻译。解析失败时静默忽略。 |
| 11 | status_words | 选填 | 多行文本，每行 `值 中文\|英文` | 状态字：把整数值映射为状态描述，如 `0 分闸\|Open`。格式同 Modbus 点表。 |
| 12 | warn_bits | 选填 | **恰好 16 行**，每行 `中文\|英文\|等级` | 告警位：把值按位展开为 16 个独立告警，第 i 行对应 bit i。等级可省略（缺省 `0`）。格式同 Modbus 点表。 |
| 13 | level | 选填 | `0`/空/`1`/`2`/`3` | 单点告警等级：值非 0 即命中该等级。`1`/`2`/`3` 对应 `Normal`/`High`/`Critical`。 |

第 11、12 列有内容但格式不对时，会在日志里记一条 `IEC104点表 ... 解析失败, 已忽略` 的警告，该列按未配置处理，不影响整行。

## type 取值

| type | 含义 | 方向 | 对应 104 报文 |
|---|---|---|---|
| `yx` | 遥信，开关量状态 | 上行 | M_SP_NA_1 / M_SP_TB_1（单点）、M_DP_NA_1 / M_DP_TB_1（双点） |
| `yc` | 遥测，模拟量 | 上行 | M_ME_NA_1 / M_ME_TD_1（归一化）、M_ME_NB_1 / M_ME_TE_1（标度化）、M_ME_NC_1 / M_ME_TF_1（短浮点） |
| `yk` | 单点遥控 | 下行 | C_SC_NA_1 |
| `yk_double` | 双点遥控 | 下行 | C_DC_NA_1 |
| `yt_short` | 遥调，短浮点设定值 | 下行 | C_SE_NC_1 |
| `yt_scaled` | 遥调，标度化设定值 | 下行 | C_SE_NB_1 |
| `yt_normalized` | 遥调，归一化设定值 | 下行 | C_SE_NA_1 |
| `yt_step` | 步位置命令 | 下行 | C_RC_NA_1 |

- **上行点**只需要 `ca + ioa` 就能匹配，具体用单点还是双点、哪种测量值类型由对端决定，点表里只分遥信和遥测。
- **下行点**由我们构造报文，必须明确命令类型。遥调选哪种，要看对端的规约说明，选错会被对端拒绝。
- 带 CP56Time2a 时标的类型（`_TB_1`、`_TD_1` 等）可以正常接收，**时标被忽略**，入库时间以采集器收到的时刻为准。
- 其他报文类型（累计量 M_IT、位串 M_BO 等）不支持，收到会被忽略。

## 上行：值怎么转换

匹配方式：收到 ASDU 后，对其中每个信息对象，用 `(ca, ioa)` 在**启用的 `yx`/`yc` 点**里查找，找到才入库，找不到直接丢弃。

| 点类型 | 收到的报文 | 入库的值 |
|---|---|---|
| `yx` | 单点 | `Val::U8`，`0`=分，`1`=合 |
| `yx` | 双点 | `Val::U8`，`0`=中间态，`1`=分，`2`=合，`3`=不确定 |
| `yc` | 归一化 / 标度化 / 短浮点 | `Val::F64`，`原始值 × scale + offset` |

- `yx` 点收到测量值、`yc` 点收到遥信值，类型不匹配时丢弃。
- `scale`/`offset` 对遥信无效。
- 短浮点按最短十进制表示还原为 `f64`，不会出现 `220.10000610…` 这样的二进制误差。
- **质量位被忽略**：对端标了无效、被封锁、非当前值的点照样入库。

## 下行：值怎么编码

通过 `DataCenter::dispatch` 下发，下发目标可以按 `id`、`key` 或 `name` 引用。**只有启用的控制类点**（`yk` 到 `yt_step`）能被找到。所有命令都是**直接执行**，不做选择预置。

| 点类型 | 下发值 | 编码 |
|---|---|---|
| `yk` | 任意数值，非 0 为合，0 为分 | 单点命令 |
| `yk_double` | `1`=分，`2`=合，其他值被拒绝 | 双点命令 |
| `yt_short` | 工程值 `v` | 发送 `(v - offset) / scale`，转 `f32` |
| `yt_scaled` | 工程值 `v` | `round((v - offset) / scale)`，必须在 `-32768~32767` 内，否则被拒绝 |
| `yt_normalized` | 工程值 `v` | `(v - offset) / scale`，必须在 `-1~1` 内，否则被拒绝 |
| `yt_step` | `1`=降，`2`=升，其他值被拒绝 | 步位置命令 |

被拒绝或找不到点的下发，会在日志里记 `IEC104下发失败` / `未找到控制点配置` 的警告，不影响同一批里的其他点。

## 遥控遥调的值能读回吗

**不能直接读。** IEC 104 的控制方向只有"下发命令"，没有读取控制点当前值的机制。命令的应答（ACT_CON）只表示被接受或拒绝，不带当前值。

回读要靠对端把结果映射到监视点：

- 遥控的结果，通常看对应的遥信（如断路器位置）。
- 遥调的结果，要看对端有没有提供设定值回显遥测。

有些厂家让回读点与控制点**共用同一个 IOA**（两个方向的地址空间相互独立）。这种情况下点表写两行：一行 `yk`/`yt_*` 用于下发，一行 `yx`/`yc` 用于回读，`ca`、`ioa` 相同，`id`、`key` 不同。

## 总召唤与突发上送

- 连接建立后，先发 STARTDT，再对点表里**出现过的每个 CA**（仅统计启用的 `yx`/`yc` 点）各发一次站总召唤。
- 总召内容：对端回 ACT_CON，上送其当前所有遥信遥测，再回 ACT_TERM。**总召范围由对端决定**，点表里配了的点，对端不一定在总召里上送。
- 配置了 `interval` 的话，之后按周期重复总召，用于校准漏掉的变位。
- 数据变化时对端会主动突发上送，不依赖总召。
- 遥控遥调点没有"当前值"，不会出现在总召结果里。

## 通讯状态点

每个 IEC 104 设备会自动上报一个通讯状态点，不需要在点表里配置：

| 属性 | 值 |
|---|---|
| id | `65535`（`0xFFFF`） |
| key | `communicationStatus` |
| name | 通讯状态 |
| 值 | `0` = 通讯正常，`1` = 无通讯 |

设备启动后、连接建立前、断线重连期间、停止后均为 `1`；连接成功并发出总召后置为 `0`（不等总召数据全部到达）。点表里的 id 不能占用 `65535`。

## 告警相关的两套机制

两者等级编码一致：`0`=不告警，`1`=Normal，`2`=High，`3`=Critical。

1. **warn_bits（第 12 列）**：一个整数值打包 16 个 bit，每个 bit 各自定义名称和等级。适合对端把多个告警位打包成一个整数**遥测**（如故障字）上送的场景。
2. **level（第 13 列）**：整个点本身就是一个告警，值非 0 即命中该等级。适合**遥信**（如保护动作）。

IEC 104 的单点遥信只有 1 位，所以一个遥信只能表示一个告警，用 `level` 即可。两列可以分别用在不同的点上，同一点上同时配置不建议，容易产生重复告警。

## 校验规则

点表解析按行进行，**出错的行会被跳过**并在日志里记 error，不会导致整份点表加载失败（这一点与 Modbus 点表里 id 重复会整份失败不同）。

| 情况 | 结果 |
|---|---|
| 必填列为空、类型非法 | 该行被跳过，日志说明哪一列 |
| `ca` 不在 `1~65534`、`ioa` 不在 `1~16777215` | 该行被跳过 |
| `scale` 为 `0` | 该行被跳过 |
| `id` 为 `65535`，或与前面的点重复 | 该行被跳过（先出现的保留） |
| 同一 `(ca, ioa)` 有多个**监视点** | 后出现的被跳过 |
| 同一 `(ca, ioa)` 有多个**控制点** | 后出现的被跳过 |
| 同一 `(ca, ioa)` 一个监视点 + 一个控制点 | 允许，用于回读 |

`register_file` 未配置、文件打不开时，设备创建失败，日志提示"找不到点位表"。点表文件能打开但没有 `iec104` sheet、或所有行都出错时，设备仍会创建并连接，只是没有任何点，日志会提示 `点表中没有启用的遥信/遥测点, 不会发送总召唤`。

| 4001 | powerSetpoint | 1 | 25089 | yt_short | 1 | 0 | 短浮点设点 |

## 联调

没有真实设备时，可以用仓库自带的模拟子站：

```bash
# 终端 1：模拟子站，点位与示例点表对应
cargo run -p collector-iec60870 --example slave            # 默认端口 2404

# 终端 2：用示例配置启动采集器
cargo run -p collector-cmd --bin colld -- -c config/iec104/config_示例.json

# 自动化联调测试（总召、突发上送、6 种命令下发、断线重连）
cargo test -p collector-core iec60870_dev::tests
```

## 常见问题

| 现象 | 排查 |
|---|---|
| 设备一直"连接中"/"失败" | 核对 `ip`/`port`，确认子站允许主站连接；`timeout` 过小也会导致连接超时。 |
| 已连接，但某个点一直没有值 | 核对点表的 `ca`、`ioa` 是否与对端地址表一致（十进制）；确认对端总召范围包含该点；确认该行没有被校验规则跳过（看启动日志）。 |
| 值有但数量级不对 | 检查 `scale`/`offset`；归一化遥测的原始值在 -1~1，需要通过 `scale` 还原为工程值。 |
| 下发无反应 | 看日志有无 `IEC104下发失败`；确认 `type` 与对端要求的命令类型一致，对端是否要求"选择/执行"两步（当前只支持直接执行）。 |
| 遥控后读不到结果 | 控制点无法读回，需要配置对应的遥信或遥测回读点，见"遥控遥调的值能读回吗"。 |

## 当前限制

- 遥控、遥调只做直接执行，没有选择/执行两步，也不跟踪 ACT_CON 结果，被拒只记日志。
- 质量位和时标被忽略。
- 不支持时钟同步、累计量、读命令（C_RD_NA_1）。
- 一个设备只对应一个子站连接，不支持冗余通道。
- 不支持 TLS。
